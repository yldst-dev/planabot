# 대화 아키텍처와 프라나 문체 개선

확인일: 2026-09-14.

기본 live 프롬프트, OpenRouter의 대화 구성, 추가 호출 조건과 측정 기능을 개선했습니다. 기존 대화 저장소를 삭제하거나 이전 원본 프로필을 덮어쓰지 않았습니다. 의존성과 라이브러리 버전은 변경하지 않았습니다.

## 적용한 구조

| 영역 | 변경 내용 |
|---|---|
| 시스템 규칙 | 사용자 요청과 외부 참고 자료를 구분하고, 반복되는 보안 문장을 줄였습니다. 검색 여부는 검색 정책에서 결정합니다. |
| 문체 | 한국어 어미, 독립된 호칭 줄, 짧은 인사, 요청한 문장 수를 명시했습니다. 인사·감사·걱정·불확실성·설명의 예시를 넣었습니다. |
| 장면 구분 | 일반 인사에서 접촉 장면, 생활 지도, 약속을 먼저 추가하지 않도록 했습니다. 조건부 장면 지시는 사용자 자료에 섞지 않고 시스템 조립에서 처리합니다. |
| 공통 조립 | 일반 모드와 연속 모드가 buildChatSystemPrompt와 buildTurnMessages를 공유합니다. Geminiweb의 기존 전송 기록 재사용 경로는 따로 유지합니다. |
| 대화 재생 | OpenRouter를 포함한 일반 제공 경로에서는 과거 검색 본문과 메타정보 대신 사용자 발화와 전달한 최종 답변을 재생합니다. 발화자 ID는 보존합니다. |
| 기억 | 남아 있는 대화와 역할까지 같은 기억 항목은 중복으로 보내지 않습니다. 다른 발화자 항목과 요약은 유지합니다. 단순 인사는 장기 기억을 추가하지 않습니다. |
| 길이 제한 | 시스템·현재 질문·현재 근거·답장 문맥은 보호합니다. 오래된 대화 쌍부터 제거하고, 이어서 선택적 기억을 제거합니다. 필수 자료만으로도 24000토큰을 넘으면 오류를 반환합니다. |
| 대화 연속성 | OpenRouter에서는 한도를 넘었다고 대화 전체를 초기화하지 않고 최근 대화 쌍을 남깁니다. 저장된 epoch와 장기 요약 체계는 유지합니다. |
| 검색어 | 문맥 보충이 필요하지 않은 120자 이하 검색어는 추가 모델 호출 없이 사용합니다. 후속 정정이나 긴 질의는 기존 재작성 경로를 유지합니다. |
| 이어쓰기 | 첫 호출의 중복된 토큰 계산을 줄이고, 이어쓰기 결과는 마지막 조각이 아닌 전체 답변으로 기록합니다. 추가 요청에도 길이 제한을 적용합니다. |
| 전달 | 호칭과 줄바꿈은 로컬에서 정리합니다. 잘림 판정은 기존 공통 함수를 재사용하며, 제공업체의 길이 제한 종료도 재작성 조건에 반영합니다. |
| 재작성 보호 | 초안과 재작성 결과의 숫자 및 대표적인 부정 표현이 달라지면 초안을 유지합니다. 검증된 출처가 있는 답변은 기존처럼 출처를 붙이고 불필요한 재작성을 하지 않습니다. |
| 추론 예산 | GLM의 전체 출력 예산을 Telegram 최종 답변 길이로 줄이지 않습니다. 명확한 인사·감사는 기본 설정에서만 low를 사용합니다. |
| 측정 | 실제 제공업체·응답 모델·캐시 토큰·추론 토큰·보고된 비용을 기존 실행 로그에 추가했습니다. 비밀 값이나 사용자 대화 본문을 운영 측정 로그에 추가하지 않습니다. |
| 재시도 | 호출 예산이 소진되면 기다렸다가 다시 실패하는 대신 원래 제공업체 오류를 반환합니다. 평가 도구는 오류가 3회 누적되면 중단합니다. |

숫자·부정 표현 검사는 의미 동일성의 완전한 증명이 아닙니다. 고유명사, 단위, 조건의 모든 변화를 검출하지 못하므로 검증된 검색 답변은 재작성하지 않는 기존 정책을 유지합니다.

과거의 잘못된 말투를 일괄 삭제하지는 않습니다. 새로운 규칙과 예시를 고정 시스템 영역에 두고, 재생 시 내부 추론과 출처 표시를 정리합니다. 이미 저장된 원문 가운데 현재 형식으로 확인할 수 없는 기록은 저장된 정리 문장을 사용합니다.

## OpenRouter 설정

2026-09-14에 OpenRouter의 모델 및 endpoint 목록에서 z-ai/glm-5.3-flash를 확인했습니다. reasoning은 필수이며 지원 effort는 low, high, max입니다. 모델 목록의 기본값은 max이고, 샘플링 기본값은 temperature 1과 top_p 0.95입니다. 이 지원 정보는 제공업체 및 시점에 따라 다시 확인해야 합니다. [모델 목록](https://openrouter.ai/api/v1/models), [제공업체 목록](https://openrouter.ai/api/v1/models/z-ai/glm-5.3-flash/endpoints)

프로젝트의 기존 temperature 1.0과 top_p 0.7은 유지했습니다. 문체 개선 효과와 샘플링 변경 효과를 혼동하지 않기 위해 모든 제공업체에 새 기본값을 일괄 적용하지 않았습니다.

| 설정 | 처리 |
|---|---|
| PLANABRAIN_OPENROUTER_TEMPERATURE | 선택 사항이며 0부터 2까지 허용합니다. 빈 값은 기존 기본값을 사용합니다. |
| PLANABRAIN_OPENROUTER_TOP_P | 선택 사항이며 0부터 1까지 허용합니다. 빈 값은 기존 기본값을 사용합니다. |
| PLANABRAIN_OPENROUTER_PROVIDER_ORDER | 쉼표로 구분한 제공업체 slug입니다. 지정하면 목록 바깥으로의 fallback을 끕니다. 빈 값은 기존 라우팅을 유지합니다. |
| PLANABRAIN_CHAT_THINKING_MODE=default | 일반 요청은 제공업체 기본값을 사용합니다. GLM의 명확한 인사·감사만 low로 처리합니다. |
| PLANABRAIN_CHAT_THINKING_MODE=off 또는 minimal 또는 low | GLM-5.3-flash에서는 low로 전달합니다. 추론을 끄는 설정이 아닙니다. |
| PLANABRAIN_CHAT_THINKING_MODE=medium 또는 high | GLM-5.3-flash에서 지원하는 high로 전달합니다. |

이 변환은 GLM-5.3-flash의 OpenRouter 경로에만 적용합니다. 알 수 없는 다른 모델의 추론 설정을 추측해서 추가하지 않습니다. 명시한 high 등의 설정은 인사에서도 존중합니다. reasoning.exclude는 응답에서 추론 내용을 제외하는 옵션이며 추론 연산을 끄는 옵션이 아닙니다. [OpenRouter 추론 설정](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)

프로덕션 제공업체는 고정하지 않았습니다. 비교 평가에서만 relace를 지정했습니다. 처음 시도한 DeepInfra 경로는 429를 반환해 비교 결과에서 제외했습니다. [제공업체 라우팅](https://openrouter.ai/docs/guides/routing/provider-selection)

고정 시스템 규칙과 문체 예시는 대화 앞부분에, 현재 시각과 참고 자료는 뒤에 배치합니다. 지원 여부가 확인되지 않은 cache_control을 강제로 추가하거나 캐시를 위해 무의미한 문장을 채우지 않았습니다. 캐시 효과는 응답의 cached_tokens로 확인합니다. [캐시 안내](https://openrouter.ai/docs/guides/best-practices/prompt-caching)

## 실제 모델 평가

[평가 원자료](evaluations/prana-optimization-2026-09-14.json)에 답변, 설정, 자동 검사, 제공업체, 토큰, 응답 시간과 비용을 남겼습니다. 원자료는 합성한 평가 문장과 그 응답으로 구성되며 실제 사용자 대화 기록을 포함하지 않습니다.

프롬프트 비교는 모델 z-ai/glm-5.3-flash, 제공업체 Relace, temperature 1.0, top_p 0.7, 추론 기본값, max_tokens 2048로 진행했습니다. 각 질문을 기존·개선 프롬프트로 각각 2회 호출했고, 2회차에는 순서를 바꿨습니다. baseline은 커밋 26fff672e9e97220122c84fb3243be839f2de347의 기본 프롬프트와 검색 불가 규칙을 조립한 것입니다. 개인 식별용 정적 규칙 1줄은 비교 입력에서 제외했습니다.

아래 프롬프트 비교는 시스템 프롬프트 효과를 따로 보는 호출입니다. 일부 질문은 문체 예시와 겹치는 회귀 검사입니다. 이후 전체 처리 경로와 예시에 없는 표현 10개를 별도로 확인했습니다.

| 항목 | 기존 프롬프트 | 개선 프롬프트 |
|---|---:|---:|
| 답변 수 | 20 | 20 |
| 자동 검사 전체 통과 | 6 | 20 |
| 입력 토큰 합계 | 37676 | 26416 |
| 출력 토큰 합계 | 5782 | 4716 |
| 캐시 입력 토큰 합계 | 37120 | 17920 |
| 응답 시간 중앙값 | 1960ms | 3784.5ms |
| 보고된 비용 합계 | 0.002428272USD | 0.002476980USD |

입력 토큰은 약 29.9퍼센트, 출력 토큰은 약 18.4퍼센트 줄었습니다. 그러나 이 실험에서는 기존 프롬프트의 캐시 사용량이 더 높았고 개선 프롬프트의 시간과 비용이 더 낮지는 않았습니다. 공급자 부하와 캐시 상태를 통제하지 않았으므로 보편적인 시간·비용 절감률로 해석하면 안 됩니다. 비용은 모델 응답의 usage.cost를 그대로 합산했으며 별도 가격표로 추정하지 않았습니다. [사용량과 비용 안내](https://openrouter.ai/docs/cookbook/administration/usage-accounting)

명확한 인사 4개에 대한 low 추론 실험에서는 4개가 모두 자동 검사를 통과했고 응답 시간 중앙값은 1384ms였습니다. 이 결과를 근거로 단순 인사에만 low를 자동 적용했습니다. 설명, 검색, 이미지 입력, 복합 요청에는 이 분기를 적용하지 않습니다.

### 최종 전체 처리 경로

| 검사 | 결과 |
|---|---|
| 인사·설명·정정·숫자·인용 지시 등 10개 요청 | 10개 모두 자동 검사 통과, 요청별 모델 호출 1회 |
| 프롬프트 예시에 없는 표현 10개 | 10개 모두 자동 검사 통과, 요청별 모델 호출 1회 |
| 합성한 대화 10회분을 넣은 인사 4개 | 4개 통과, 요청별 호출 1회, 중앙값 1403ms |
| 합성한 대화 30회분을 넣은 인사 4개 | 4개 통과, 요청별 호출 1회, 중앙값 1186.5ms |
| 긴 기록의 재생 범위 | 40개 메시지 한도에서 현재 턴을 위한 2개를 제외한 최근 대화 유지 |

긴 기록 검사는 실제 30회 연속 응답을 생성한 실험이 아니라 합성한 기록을 입력한 검사입니다. Telegram 전송과 실제 운영 메모리 압축을 포함하는 장시간 운영 실험은 아닙니다.

밤 인사에 대한 최종 처리 경로의 실제 응답은 다음과 같습니다.

```text
선생님.
좋은 밤입니다.
```

2문장 요약 요청에서는 다음처럼 호칭과 서두를 생략하고 값과 부정을 유지했습니다.

```text
파일 용량은 519MB이고 재생 시간은 23분 42초입니다.
업로드는 아직 완료되지 않았습니다.
```

자동 검사는 호칭 줄, 마크다운, 이모티콘, 짧은 응답의 행동 묘사·길이, 알려진 문법 오류, 숫자 사례의 값·부정·문장 수를 확인합니다. 일반적인 한국어 문법이나 원작 프라나 말투의 완전한 재현을 판정하는 검사가 아닙니다. 사람의 별도 문체 점수는 아직 없으며 평가용 예시는 원작 대사 인용이 아닙니다.

## 재실행

planabrain 폴더에서 실행합니다. 기본 명령은 네트워크를 사용하지 않고 프롬프트 크기를 출력합니다.

```sh
npm run eval:prana
```

실제 호출은 --live를 명시해야 합니다. 자격 증명은 지정한 환경 파일에서 읽으며 출력하지 않습니다. 다음 명령은 실제 호출 비용이 발생하는 평가입니다.

```sh
npm run eval:prana -- --live --model z-ai/glm-5.3-flash --provider relace --repeats 2 --output /tmp/prana-evaluation.jsonl
npm run eval:prana -- --live --pipeline --model z-ai/glm-5.3-flash --provider relace --history-turns 30 --limit 4 --output /tmp/prana-history.jsonl
npm run eval:prana -- --live --model z-ai/glm-5.3-flash --provider relace --thinking low --limit 4 --output /tmp/prana-low.jsonl
```

--holdout을 지정하면 프롬프트 예시에 없는 표현 10개를 사용합니다.

--baseline-prompt는 prompt 문자열을 가진 JSON 파일을 받아 같은 조건으로 비교합니다. --pipeline과 함께 사용할 수 없습니다. 기존 프롬프트에 비밀 값이나 개인 식별 정보가 없는지 확인한 후 사용합니다. --env는 환경 파일 경로를 바꿉니다. --top-p는 평가에서만 샘플링 값을 바꿉니다. --limit는 1부터 10까지, --repeats는 1부터 3까지 허용합니다. --history-turns는 0, 10, 30을 지원합니다.

전체 경로 평가의 thinking 필드는 요청한 설정입니다. default일 때 명확한 인사에는 내부 분기에서 low가 적용됩니다. 실제 요청에 대한 이 변환은 전송 payload를 확인하는 테스트로 검증합니다.

## 코드 검증과 적용 범위
